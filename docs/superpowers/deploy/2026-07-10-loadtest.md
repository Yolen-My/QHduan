# 压测方案与验收

## 环境
- 在演练用 PocketBase 数据库(拷贝 pb_data)上执行,严禁对正式库压测。
- 造数:用 scripts/ 下现有脚本或 PB Admin 批量导入 1000 名玩家。

## 执行

```bash
# 观众 + 只读混合
k6 run -e BASE=https://<域名> -e WS=wss://<域名>/ws -e VUS=1000 scripts/loadtest/k6-mixed.js
# 写路径(判分风暴演练):压测运行中,admin 页触发 bingo 判分
```

## 验收标准(设计文档第 8 节)

| 指标 | 阈值 | 采集方式 |
|---|---|---|
| 提交/个人读 P95 | < 1s | k6 http_req_duration |
| 排行榜推送延迟 | < 2s | 手改分数→大屏变化秒表/日志时间差 |
| PocketBase CPU | < 50% | top / vmstat |
| 公网下行带宽 | < 15Mbps | 云控制台监控 |
| WS 断线重连 | 杀 gateway 后 10s 内降级轮询,重启后回连 | 手工演练 |
| Bingo 判分 | 1000 玩家 < 5s 完成,期间页面不卡死 | admin 触发计时 |

## 本地小规模验证(VUS=50)

本地试跑仅用于脚本正确性验证,不代表生产容量。1000 VU 验收须在正式服务器上执行。

```bash
# 前置:起全栈
cp -R pb_data /tmp/pb_smoke16
# 终端 1:PocketBase
./pocketbase serve --http=127.0.0.1:8098 --dir=/tmp/pb_smoke16
# 终端 2:WS 网关
cd gateway && POCKETBASE_SERVER_URL=http://127.0.0.1:8098 node index.js
# 终端 3:Next.js(生产模式)
POCKETBASE_SERVER_URL=http://127.0.0.1:8098 npm run build && \
POCKETBASE_SERVER_URL=http://127.0.0.1:8098 npm run start

# Docker 试跑(macOS host.docker.internal 访问宿主机)
docker run --rm -i \
  -v "$PWD/scripts/loadtest:/scripts" \
  grafana/k6 run \
  -e BASE=http://host.docker.internal:3000 \
  -e WS=ws://host.docker.internal:8100 \
  -e VUS=50 \
  /scripts/k6-mixed.js
```

### 清理

```bash
# 杀后台进程
pkill -f "pocketbase serve" || true
pkill -f "gateway/index.js" || true
pkill -f "next start" || true
# 删演练数据
rm -rf /tmp/pb_smoke16
redis-cli del snap:ranking snap:games snap:fullranking snap:admin
```

## 场景说明

| 场景 | 比例 | 行为 |
|---|---|---|
| ws_audience | 80% VU | 建立 WS 长连,接收快照推送;断线重连由客户端处理 |
| submitters | 每秒 50 次 | GET /api/state + GET /api/questions/quiz(只读混合) |

## 写路径扩展

如需压测写路径(答题提交、bingo 判分),需先在演练库中批量创建玩家 session,再对以下接口施压:

- 答题提交 — 玩家直连 PocketBase(生产经 Nginx `/pb`),对 `game_results` collection 写入(见 lib/pb-storage.ts `submitGameResult`)。
- `POST /api/admin/bingo-score` — 手动触发判分,需携带管理员会话 cookie(`admin_session`,先 `POST /api/admin-login` 获取)。

写路径压测建议配合 k6 `SharedArray` 预加载玩家 token,避免登录接口成为瓶颈。
